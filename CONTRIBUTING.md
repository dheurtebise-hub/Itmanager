# 🤝 Guide de contribution

Merci de votre intérêt pour contribuer à IT Ticket Manager !

## 🚀 Démarrage rapide

1. **Fork** le projet
2. **Clone** votre fork
3. Créez une **branche** pour votre fonctionnalité
4. **Committez** vos changements
5. **Poussez** vers votre fork
6. Ouvrez une **Pull Request**

## 📋 Standards de code

### Python
- Suivre PEP 8
- Docstrings pour toutes les fonctions publiques
- Type hints recommandés
- Tests unitaires pour les nouvelles fonctionnalités

### JavaScript
- Vanilla JS (pas de framework)
- Commentaires pour les fonctions complexes
- Nommage en camelCase

### CSS
- Variables CSS pour les thèmes
- Classes BEM-like
- Mobile-first quand applicable

## 🧪 Tests

Exécutez les tests avant de soumettre :

```bash
pytest tests/ -v
```

## 📝 Commit Messages

Format recommandé :

```
type(scope): description courte

Description détaillée si nécessaire

Fixes #123
```

Types :
- `feat`: Nouvelle fonctionnalité
- `fix`: Correction de bug
- `docs`: Documentation
- `style`: Formatage
- `refactor`: Refactoring
- `test`: Tests
- `chore`: Maintenance

## 🐛 Rapporter un bug

Utilisez le template d'issue GitHub avec :
- Description du problème
- Étapes pour reproduire
- Comportement attendu vs actuel
- Environnement (OS, version Python, etc.)

## 💡 Proposer une fonctionnalité

1. Vérifiez qu'elle n'existe pas déjà
2. Ouvrez une issue de discussion
3. Attendez les retours avant d'implémenter

## ✅ Checklist avant PR

- [ ] Code testé localement
- [ ] Tests unitaires ajoutés/mis à jour
- [ ] Documentation mise à jour
- [ ] Pas de conflits avec main
- [ ] Commits clairs et atomiques
